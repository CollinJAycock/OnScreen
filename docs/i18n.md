## How it works

`web/src/lib/i18n/index.svelte.ts` is about 250 lines with no dependencies,
so the TV web apps can use the same file:

- **Catalogs** are flat JSON in `web/src/lib/i18n/locales/<language>/`, one
  file per area of the app, merged by that folder's `index.ts`. English (`en/`)
  is the source and is bundled; `es/` and `zh-Hans/` load only when chosen.
  A key lives in exactly one area file, and every language has the same
  files; the catalog test checks both.

  | File | What it holds | Key prefixes |
  |---|---|---|
  | `core.json` | Shared words, the app shell (sidebar, user switcher, server screens), sign-in, the language picker | `common.`, `nav.`, `shell.`, `switcher.`, `server.`, `login.`, `language.` |
  | `settings-a.json` | Settings: the main page, Transcode, Users, SSO, Tasks, Optimized, Scrobble, Audit | `settings.<page>.` |
  | `settings-b.json` | The other Settings pages (TV, *arr services, plugins, storage, webhooks, notifications, backup, …) | `settings.<page>.` |
  | `components.json` | The player (`/watch`), the shared components in `lib/components`, the native-app pages, the shared helpers in `web/src/lib` (`lib.<module>.`, e.g. `lib.watchState.`) | `player.`, `ui.`, `native.`, `lib.` |
  | `media.json` | Browsing: libraries, photos, collections, playlists, TV guide, podcasts, books, search, history, … | one prefix per page, e.g. `library.`, `photos.` |
  | `account.json` | Requests, account, analytics, profiles, invite, setup, password reset, pairing | one prefix per page, e.g. `requests.`, `account.` |
- **Lookup:** the active language, then English, then the key itself. A
  string missing from a translation therefore shows in English, never blank.
- **Plurals** use the browser's `Intl.PluralRules`: `key_one`, `key_few`,
  `key_many`, `key_other`, falling back to `key_other`. Each language has only
  the forms it uses (Chinese has only `_other`; Spanish has `_one`,
  `_many`, `_other`).
- **Numbers** in placeholders use the language's style (`1,234` / `1.234`).

**Which language is used:**
1. Signed in, the **account's** choice (`ui_language` in
   `GET /users/me/preferences`), set from **Account › Languages**. It is
   remembered on the device.
2. Otherwise this **device's** choice: the picker on the sign-in screen
   (`localStorage` `onscreen.locale`).
3. Otherwise the **browser's** languages (`navigator.languages`): `es-*` is
   Spanish, and `zh`, `zh-CN`, `zh-SG`, `zh-Hans*` are Simplified Chinese.
   Traditional Chinese (`zh-TW`, `zh-HK`, `zh-Hant`) isn't shipped, so the
   next language in the list decides.
4. Otherwise English.

"Device language" in the picker clears the choice (on the account too, from
the Account page).

**Server:** `users.ui_language` (migration 00063, limited by a CHECK to the
shipped tags), returned by `GET /users/me/preferences` and set by
`PUT /users/me/ui-language` (`null` or `""` clears it). It has its own
endpoint because the preferences PUT rewrites both media-language fields.
`SupportedUILanguages` in `internal/api/v1/users.go` mirrors the CHECK.

## Writing translatable UI

**In templates, use the `$i18n` store** (not `tr`: that name would clash with the HTML `<tr>` element on table pages):

```svelte
<script lang="ts">
  import { t, i18n } from '$lib/i18n/index.svelte';
</script>

<h1>{$i18n('server.cantConnect')}</h1>
<button aria-label={$i18n('shell.switchUser')}>…</button>
<span title={$i18n.n('nav.requestsWaiting', count)}>…</span>
<p>
  {#each $i18n.rich('server.savedNote', { changeServer: $i18n('login.changeServer'), server: $i18n('nav.server') }) as seg}
    {#if seg.param}<strong>{seg.text}</strong>{:else}{seg.text}{/if}
  {/each}
</p>
```

- **Why the store:** most components are legacy (non-runes) Svelte. There
  the compiler treats a bare `{t('…')}` as static, so it renders once and
  doesn't change with the language. `$i18n` re-renders everywhere. A test in
  `login.test.ts` guards this.
- **In script code** that runs at a moment in time, plain `t()` is right,
  e.g. `error = t('login.incorrect')`.
- **`tRich` / `$i18n.rich`** split a message around its placeholders, so the
  template can style the filled-in values (bold, code) without `{@html}`.
  Values stay plain text, and translators can move the placeholder.

**Rules for strings:**
- **Whole sentences**, with placeholders for the variable parts. Never join
  translated pieces: word order differs.
- **Placeholders** are `{name}`, and a translation must keep exactly the same
  set. The catalog test enforces this.
- **Plurals:** give English `_one` and `_other`, and call `tn` / `$i18n.n`
  with the count. Never `count === 1 ? … : …`.
- **Keys** are `area.thing` in camelCase: `nav.home`, `login.forgotPassword`,
  `shell.viewingAs`. Put widely shared words under `common.`.
- **Never translated:** OnScreen, provider names (`OIDC`, `SAML`, an IdP's
  display name), codec and format names, and the language names in the picker,
  which always show in their own language.
- **Server messages** shown as-is (`e.message`) are still English: stage 5.
- **The privacy policy** (`/privacy`) stays English: it is legal text, and a
  machine draft of it would be worse than none. Translate it only with a
  reviewed translation.

## Adding a string

1. Add the key to the area's file in `locales/en/` (the table above).
   TypeScript then accepts it in `t()` / `$i18n()`.
2. Use it.
3. Optionally add drafts to the same file under `locales/es/` and
   `locales/zh-Hans/`. Untranslated keys fall back to English, and the
   catalog test lists them.

## Adding a language

1. Add a migration widening the `users.ui_language` CHECK, and add the tag to
   `SupportedUILanguages` (`internal/api/v1/users.go`) and to the OpenAPI
   enum.
2. Add the tag to `LOCALES`, `LOCALE_NAMES` (its own name for itself),
   `loaders` and `PAGE_LANG` (the page's `lang`, which picks the system
   font) in `index.svelte.ts`. Teach `matchLocale` its browser tags.
3. Add `locales/<tag>/` with the same area files as `en/` and an
   `index.ts` like the others, then add it to the catalog test's map.
4. For TV apps and Roku, check that the platform's fonts cover the script.

## For translators

- Each file is one flat JSON object: `"key": "text"`, and each language has
  one file per area of the app. Translate the text only. Keep `{placeholders}` exactly as written, though you may move them.
- **Plural keys** end in `_one`, `_few`, `_many` or `_other`. Provide the
  forms your language uses (see CLDR plural rules). `_other` is required.
- **Tone:** informal and direct (Spanish *tú*), short labels, sentence case.
- **Typography:** use the language's own punctuation, e.g. Chinese full-width
  `，。：“”` and no space between Chinese characters. Keep a space between
  Chinese and Latin text or numbers.
- `npm test -- src/lib/i18n` checks the files. Locally on Node 26 run it with
  `NODE_OPTIONS=--no-experimental-webstorage`.

## The TV web apps

LG webOS, Samsung Tizen and the Xbox app (also served at `/tvapp/`) use the
web app's module with catalogs of their own, since their screens differ.

- **One folder, three copies.** `clients/<app>/src/lib/i18n/` is the same in
  all three apps: `index.svelte.ts` is the web app's module, copied as is, and
  `locales/` holds the TV catalogs. Each app stays self-contained (CI builds
  each from its own folder, and the release embeds `clients/xbox` alone), so
  the copies aren't shared. **Edit the webOS copy**, then run
  `node scripts/tv-i18n.mjs --sync`; CI fails when the copies differ.
- **Catalogs:**

  | File | What it holds | Key prefixes |
  |---|---|---|
  | `core.json` | Shared words, the top bar, the exit popup, the on-screen keyboard, setup, sign-in, pairing, Settings (with Scrobbling and Licence & terms) | `common.`, `nav.`, `exit.`, `keyboard.`, `language.`, `setup.`, `login.`, `pair.`, `settings.`, `prefs.`, `scrobble.`, `legal.` |
  | `languages.json` | The names of audio and subtitle languages, regions and scripts (`lib/langName`: Chromium 79 has no `Intl.DisplayNames`), and the track-label words | `lang.`, `region.`, `script.`, `track.` |
- **Which language:** the same order as the web app. Before sign-in the
  device's language decides (`navigator.languages`). The first screen waits
  for it, so nothing flashes in English.
- **The account's choice** arrives with every `GET /users/me/preferences`
  (`lib/i18n/account.ts`): the hub reads them on each visit, so it applies
  right after sign-in and when it was changed on another device. A read that
  was already out when the language was changed on this TV is ignored.
- **Settings › Language** picks Device language, English, Español or 简体中文.
  It switches at once and saves to the account (`PUT /users/me/ui-language`);
  when that fails (a server before v3), the language stays on this TV and the
  row says so.
- **Labels built in `lib`** (Settings' choices, the scrobble badge, track
  names) are getters or functions that call `t()` when shown, never strings
  built at import time, so they follow a language change.
- **Kept in English:** the licence and terms text (only the screen's headings
  are translated, with a note), and the Xbox Diagnostics screen, a support tool
  made of codec and API names.
- **The on-screen keyboard** types Latin letters only: user names, passwords,
  addresses and tokens are entered as before.
- `src/lib/i18n/screens.test.ts` renders the translated screens in Chinese and
  fails on any English left. Add a screen there when its stage lands.
- **Fonts** (checked 2026-11-10; the apps bundle none). The page's `lang`
  picks the system font, so Simplified Chinese is marked **`zh-CN`**, not
  `zh-Hans` (`PAGE_LANG` in the module):
  - The LG C1 (webOS 6) draws Chinese and Latin in its own font, LG Display,
    with either tag.
  - The Samsung Q80B (Tizen 6.5) has a Chinese font, SamsungOneUISCN, but
    uses it only for `zh-CN`. For `zh-Hans`, `zh` or `zh-Hans-CN` it draws
    every character its Korean font also has in that font, so one word mixes
    two fonts.
  - To check a TV, ask DevTools which fonts drew the text
    (`CSS.getPlatformFontsForNode`): a Korean or Japanese font in the list
    is the same problem.
- **Still to check on the TVs:** the Xbox's fonts, and that
  `navigator.languages` follows each TV's menu language.

## Notes for the next stages

  the item details (`details.json`) and the player (`player.json`), each its
  own area file. Dates use `toLocaleDateString(locale())`.

  device language, and the font must cover CJK.

  should become codes that clients translate; emails use the recipient's
  `ui_language`.
