# v2.5 Roadmap — and the 2026-H2 platform horizon

State snapshot 2026-08-05, `main` @ `de4558b` (clean). Produced from a
full-tree survey: server subsystems, all seven client surfaces, media
verticals, ops/CI, product surface, release history, competitive
parity, and a non-Apple platform scan. Apple platforms (iOS, tvOS,
AirPlay sender work) are **out of scope for this roadmap** by
direction; they remain recorded in
[comparison-matrix.md](comparison-matrix.md) as the known reach trail.

**The headline is unusual: the next release is already built.**
`VERSION` says 2.4.0, the CHANGELOG carries a complete `[v2.4.0] —
unreleased` section, and main holds 358 commits over v2.3.0 — the
ABR ladder, static pre-encoded ABR, TOTP 2FA, the asset-token
migration, fleet HTTP source streaming, MediaStore/S3, HA substrate,
and a July–August playback-hardening campaign (codec demotion +
tri-state capabilities, dead-chroma detection, bounded stall recovery,
TLS-origin pairing fix) that the CHANGELOG doesn't mention yet.
**Track 0 of this roadmap is cutting that release safely.** Everything
else keys off it, because v2.4's one deliberate breaking change (the
asset-token `?token=` hard-reject) requires the client fleet to move
in lockstep — which makes distribution, not code, the critical path.

## Track 0 — Cut v2.4.0 (the release is the feature) · ~2 weeks

The risk here is documented in this repo's own history: v2.3 shipped
none of its committed tracks because an interrupt campaign displaced
them. v2.4 is eleven weeks of un-tagged work carrying the project's
first breaking change. Cut it before starting anything new.

1. **CHANGELOG backfill** — the July–August hardening campaign (~50
   audit/fix batches, codec demotion, dead-chroma detection, pairing
   fix) has zero entries. Release notes generated today would omit two
   months of security fixes.
2. **Release-engineering fixes before tagging**: `release.yml` builds
   shipping binaries on Go 1.25 while CI tests 1.26 (align, and make
   the release workflow run tests); attach desktop installers to the
   GitHub Release instead of 14-day CI artifacts.
3. **Copyright hygiene**: `web/static/goku.png` and
   `cage-superman.png` ship as hub tiles. Replace with original art
   **before** wider store distribution multiplies exposure.
4. **Asset-token lockstep sequencing**: server tag + all six client
   releases staged through their review pipelines (Play/Amazon review
   latency is the effective update channel; Tizen/webOS/Roku sideloads
   have no update channel at all — sequence them first).
5. **Doc re-snapshot at the cut** (the v2.4 roadmap itself asks for
   this): comparison-matrix.md, ARCHITECTURE.md Known Issues (stale
   `DELETE /users/me` claim), deployment.md migration table.
6. **Defaults decision recorded**: `TRANSCODE_ABR` and
   `STATIC_ABR_ENABLED` stay opt-in at the tag; flipping defaults
   waits for HW-encoder rung validation (v2.5) and the ABR
   multi-instance lock (Track 4).
7. Fold in the **scan-time media integrity probe** if it lands in time
   (in progress in a parallel worktree; catches fake/damaged releases
   at import — born from the Masters-of-the-Universe incident).

## Track 1 — Distribution wave: the fleet into stores · v2.5

The survey's sharpest finding: OnScreen's platform problem is not
missing apps — seven clients exist — it's that only **one** is in a
production store. Ordered by readiness:

1. **Play Store TV promotion** (S) — closed testing since May; the
   2026-07-31 versionCode bump shows promotion in motion. Verify the
   Play-policy soft spots (self-service account deletion exists —
   confirm the listing links it).
2. **Play phone listing** (S) — repo knowledge freezes at
   "first-review queue, 2026-05-13"; verify actual state in the
   console and remediate.
3. **Samsung Seller Office** (M) — the most submission-ready unshipped
   client: app ID allocated, description/self-checklist/assets
   in-tree, hardware-verified on a 2022 Q80B. Remaining: distributor
   cert paperwork + real channel-art PNGs.
4. **Desktop release integrity** (M) — code signing (Windows cert /
   Azure Trusted Signing), Tauri auto-updater keypair in CI secrets,
   installers attached to Releases. Kills the SmartScreen warning that
   currently greets every desktop user.
5. **CI client-artifact packaging** (M) — today every store upload is
   hand-built on one Windows machine holding all signing material.
   Move keystores to Actions secrets, build store artifacts on tag.
   This is the single biggest distribution risk found.
6. **Roku Channel Store** (M) — blocked on: real-device soak (no Roku
   hardware run recorded), channel-art binaries (images/ contains only
   a README — sideload itself is blocked), signing flow.
7. **LG Content Store** (M-L) — furthest behind: needs a real webOS
   panel soak first (see Track 3), then LG seller account + asset set.

## Track 2 — New non-Apple platforms · ranked by reuse-leverage

From the platform scan, judged against what's actually in the tree.
Effort classes assume one person.

**Committed for v2.5 (high confidence, high reuse):**

1. **Chromecast custom receiver** (M, ~2-4 wks) — the sender already
   ships in `web/src/lib/cast.ts` (direct-play v1 against the Default
   Media Receiver), and the v2.4 asset-token migration removed the
   exact auth obstacle the v1 comment deferred on. A small CAF
   receiver page hosted by the Go server unlocks transcoded-HLS
   casting and flips a matrix row vs all three competitors.
   Prereqs: $5 Cast console registration, a dongle for soak.
2. **Android Auto (audio-first)** (S-M, ~1-3 wks) — best ROI in the
   scan: the phone client's `PlaybackService` was explicitly built
   session-first for this. Upgrade to `MediaLibraryService`, add the
   car browse tree (Music / Audiobooks / Playlists / Downloads — all
   backed by existing repositories), pass Auto quality review. Turns
   the audiobook vertical into a car product.
3. **CLI / headless player (mpv)** (S, ~1-2 wks) — small Go CLI:
   pair-or-login, browse, call Decide with an mpv capability profile,
   spawn mpv with the tokened URL, post watch-events. Serves
   headless/RPi users **and becomes the playback-matrix QA tool**.
4. **Linux desktop completion → Flathub** (S-M) — AppImage/deb already
   build in CI; add Flatpak manifest + MPRIS (same commit as Windows
   SMTC work) + ALSA exclusive leg of the bit-perfect pillar.

**Next (v2.6, need hardware or store validation):**

5. **Steam Deck** (M) — phase 1 is free once Flathub lands (Discover
   installs it; desktop mode works). Phase 2 = a 10-foot mode route
   reusing the webOS spatial-nav pattern in the same Svelte stack.
   Needs Deck hardware for the WebKitGTK codec soak.
6. **Xbox** (M-L) — hosted-web app packaged via PWABuilder→MSIX, the
   Jellyfin precedent; the webOS client (plain `<video>`+hls.js, no
   vendor player API) is the port seed, *not* Tizen (AVPlay-coupled).
   Prereqs: $19 Partner Center, a console in Dev Mode.
7. **Kodi add-on** (M) — server is 100% ready (OpenAPI spec, Decide
   endpoint, `?token=` URLs designed for header-less players); new
   small Python codebase; free official-repo submission. Reaches the
   self-hosting demographic most likely to adopt OnScreen.
8. **OPDS 1.2 catalog feed** (S-M, server-side only) — one additive
   read-only endpoint set turns every KOReader/Kobo/Boox e-reader
   into a books client without owning a rendering surface.

**Recorded as do-not-pursue (so future surveys stop re-litigating):**
PlayStation (no open store; partner program is not viable for a
self-hosted OSS client), Nintendo Switch (no media-app category, no
reachable browser), DLNA/UPnP (standing permanent scope-out; conflicts
with the single-HLS-pipeline architecture). Wear OS beyond the free
system-media-controls tier is deferred until a watch is on hand.

## Track 3 — Client-parity honesty · v2.5

Close the gaps that make the fleet uneven behind one server:

- **Codec-demotion channel beyond web**: Tizen/webOS send *hardcoded*
  capability headers (Tizen claims HEVC+HDR for every panel, no AV1;
  Roku probes HEVC only) with no runtime correction when a panel
  overclaims. Port the web demotion-registry pattern; the server
  tri-state override is already live for everyone.
- **webOS 4K cap bug**: webOS requests max height 1080 where Tizen
  asks 2160 — 4K LG panels get 1080p. One-line class of fix.
- **Hardware soaks**: real LG panel (gates both parity claims and the
  store track), real Roku device.
- **Roku catch-up scope** (pick deliberately, it's the widest gap):
  Live TV/DVR, settings, SSO-less pairing flow polish, and the
  trickplay renderer via a **server-side BIF endpoint** (benefits
  other clients too).
- **Orphan endpoints get surfaces**: photo albums API has zero client
  UI; photo map exists only on the phone app; cross-device transfer
  has server + receivers but **no sender UI anywhere**. Ship the web
  sender + web photo map; albums UI rides the photos polish below.
- **Store-art binaries**: Roku images/, webOS icons — trivial but
  blocking.
- **Test floor**: Tizen/webOS have zero automated tests; android_native
  has 24 test files CI never runs; desktop has no cargo tests in CI.

## Track 4 — Product depth (chosen from the parity scan by fit)

Committed v2.5 (each S-M, high fit with existing architecture):

- **Trakt scrobbling** for movies/TV — the event-sourced
  `watch_events` log plus the ListenBrainz pattern make this a clean
  exporter; it's also the top ask keeping self-hosters on Jellyfin.
- **Last.fm** — end the zombie backlog: it's promised in the shipping
  v2.4 CHANGELOG text; schedule it here or strike the promise. This
  roadmap schedules it (rides the scrobble package).
- **Manual collections for movies/TV** — tables and ordered positions
  exist; extend the type CHECK + browse shelf + poster override.
- **Admin session termination** (small) — admin DELETE on another
  user's session with optional message; parity row vs all three.
- **Music browse UX** — artists/albums/genres index pages; the engine
  (bit-perfect, MusicBrainz, gapless) outclasses its own navigation.
- **Audiobook UX** — playback speed, bookmarks, sleep timer;
  Audiobookshelf is the bar and the current gap is competitive, not
  cosmetic.
- **Podcasts decision** — the type is user-visible with a stub behind
  it (the exact trust mistake the manga parking avoided). Either
  commit the RSS subscription model (M) or hide the type at creation
  like manga until it's budgeted. This roadmap says: hide in v2.5,
  build RSS in v2.6.
- **Plugin roles honesty** — `metadata`/`task` roles validate and
  silently no-op today. Either land dispatch for one of them in v2.6
  or reject them at registration; greyed UI stays either way.

Deliberately **not** picked up, respecting standing decisions:
personalized recommendations (shipped, measured, pulled — stays out),
SyncPlay, DLNA, trailers/extras, Dolby Vision, DASH, Tauri PiP,
audio passthrough (capability-profiles Phase 3 stays parked), Tidal/
Qobuz (record the re-scope: dropped unless real demand appears).

## Track 5 — Ops & quality debt · continuous through v2.5

- **Playwright + compose-E2E into CI** — the entire browser-verified
  playback surface currently runs only when someone remembers. Nightly
  scheduled run against a compose stack; the QA-targeting suite stays
  manual. Add `retryOn429` pacing to the transcode specs (known
  contention failure).
- **Client CI** — android_native unit tests, desktop `cargo test` +
  build smoke, per-client artifact builds (Track 1 item 5).
- **Alerting pack** — ship example Grafana dashboard + Alertmanager
  rules for the existing Prometheus surface (dead workers, webhook
  failure storms, `ratelimit_failopen_total`); today observability is
  pull-only.
- **Backup posture** — seed a default backup schedule on fresh
  installs + document a restore drill; today zero backups until an
  admin creates the task, and the first real restore is the first
  test.
- **ABR multi-instance lock** — `abrChildLocks` is per-process; a
  Valkey lock is required before ABR + the HA compose's replicated API
  tier can coexist. Gate `TRANSCODE_ABR` default-on behind this.
- **Doc drift into definition-of-done** — three flagship docs
  contradicted the tree in this survey; add a release-checklist line.
