# v2.7 Roadmap: everything left, in as few releases as possible

State 2026-10-19, `main` @ `8d24a5ec` (v2.6.1 tagged; v2.6.2 merged, waiting
for its QA check and tag). Built from the open items in
[v2.5-roadmap.md](v2.5-roadmap.md), the "Where OnScreen trails" list in
[comparison-matrix.md](comparison-matrix.md), the known issues in
[ARCHITECTURE.md](../ARCHITECTURE.md), the remaining phases in
[capability-profiles.md](capability-profiles.md), and the open GitHub issues.
Each item was checked against the tree, not the docs alone.

**The rule this roadmap sets: one more server release (v2.7), then only
releases for an emergency.** v2.6.0, v2.6.1 and v2.6.2 were all cut
within three days. From here:

- **Server work collects into v2.7.** A fix found before then waits for v2.7
  unless it is a security issue, data loss, or a regression that blocks
  playback. Only those get a v2.7.x patch.
- **Client store builds aren't server releases.** Android Auto, Flathub, Kodi,
  the webOS Full HD build and the Fire TV update all work against a v2.6
  server. They ship through their stores whenever they're ready and don't
  need a server tag.
- **Apple platforms are scoped out** (decided 2026-10-19): no iOS, iPadOS,
  tvOS or macOS app, because each needs a paid Apple developer account, and
  no AirPlay, since nothing Apple can be tested without the hardware.

Sizes assume one person working with agents: S ≈ a day or two, M ≈ a week,
L ≈ several weeks, XL ≈ months.

## Hardware checks: not features, done during any release's QA

- Casting from the web player, and the cast poster (v2.6.1) on a TV.
- Samsung, Xbox and Roku: the v2.6 client features on the device.
- Burned-in picture subtitles on VAAPI and QSV (known issue 12).
- TrueHD / DTS passthrough with an AV receiver (known issue 12).
- The server's play decision on Roku, Fire TV, Tizen and webOS (capability-profiles, "remaining").
- AV1 on AMF: needs an RDNA3+ GPU in a Windows box.
- VAAPI full-VRAM: needs a Linux box with an Intel GPU.
- Firestick 24 Hz modes: they're skipped, and the offered-modes log line is in place.

## Stays out (standing decisions)

DLNA, sync watch / watch parties, trailers and extras, picture-in-picture in
the Tauri desktop app, automatic face recognition in photos, DASH,
personalised recommendations (built, measured and pulled; ML recommendations scoped out for good 2026-10-19), Tidal / Qobuz
streaming (scoped out for good 2026-10-19: no open API, and the services' terms
and app-store policies don't fit), and media-request features in the
Android apps. **Apple apps** (iOS / iPadOS with offline downloads, tvOS,
and the macOS desktop build): scoped out 2026-10-19 because they need a paid
Apple developer account. **AirPlay**, even from Safari: there's no Apple hardware to test it on.
